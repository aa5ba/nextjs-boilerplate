# Project Reference

هذا المرجع يوثق استخدام التطبيق الحالي من الملفات الموجودة في المستودع. أي معلومة عن SQL أو RLS أو Grants أو Triggers أو Constraints أو Indexes أو جسم RPC الكامل غير مؤكدة ما لم تظهر في ملفات Schema أو migrations فعلية داخل المستودع.

- فرع Git الحالي عند التدقيق: `main`.
- Commit المختصر الحالي عند التدقيق: `101509c`.
- أرقام الأسطر في هذا المرجع تمثل هذه النسخة من الملفات وقت التدقيق.
- قد تكون ملفات التوثيق الحالية تغييرات محلية غير committed، لذلك لا يعني مرجع Git أن كل ملفات التوثيق محفوظة في commit.

## 12. حالة تغطية قاعدة البيانات

- هذا المرجع يوثق استخدام قاعدة البيانات من كود التطبيق.
- المستودع لا يحتوي حاليًا تعريفات SQL أو migrations كاملة حسب الفحص الحالي.
- لا يمكن تأكيد:
  - RLS.
  - Grants.
  - Triggers.
  - Constraints.
  - Indexes.
  - `SECURITY DEFINER` أو `SECURITY INVOKER`.
  - الأجسام الكاملة لـRPC.
  - الذرية الفعلية.
- حالة المرجع الحالية: مرجع التطبيق موثق، ومرجع قاعدة البيانات ينتظر سحب Schema آمنًا دون بيانات.
- لا تعتبر مراجعة قاعدة البيانات كاملة حتى تتوفر ملفات Schema الفعلية.

## 13. نقاط تحتاج فحص Supabase

- تعريفات كل RPC المذكورة أعلاه.
- سياسات RLS على جداول محطة العمل والدعم.
- صلاحيات `execute` على RPC.
- فهارس وقيود uniqueness لأرقام العقود والسندات.
- Triggers التي تسجل النشاط أو تحدث المخزون.
- هل `finance_products_inventory_summary` View أم جدول.
- هل `finance_notes` محمية فعليًا عند update/delete بـRLS.
- هل RPC الحساسة تتحقق من `branch_id` والمستخدم والصلاحية داخل SQL.
- هل `atomic` في أسماء RPC يقابله transaction فعلي في SQL.
